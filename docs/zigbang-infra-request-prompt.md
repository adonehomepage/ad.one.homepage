# 직방 red-ads-portal 인프라 요약 요청 프롬프트

아래 본문을 직방 쪽(에이전트/담당자)에 그대로 보내세요.  
**저장소 수정·커밋·푸시 금지.** 요약 마크다운만 받습니다.

---

`zigbang/red-ads-portal` 저장소는 **수정·커밋·푸시하지 마세요.** 읽기만 해서, 다른 Next.js 프로젝트(분양 랜딩 SaaS)에 참고할 **배포·환경·인프라 요약 문서**를 마크다운 한 파일로 작성해 주세요.

목적: 우리 쪽에는 아직 브랜드/법무 확정 전이라 비즈니스 로직은 가져오지 않습니다. **dev/prod(또는 staging) 환경 분리, 배포 파이프라인, 성능·인프라 최적화 패턴**만 필요합니다.

문서에 포함할 항목:

1. **환경 구성**
   - 환경 이름(local / dev / staging / prod 등)과 역할
   - 브랜치 ↔ 환경 매핑(있다면). 없으면 브랜치 없이 환경만 쓰는지
   - 공개 URL / 관리자 URL / CDN 도메인 분리 방식

2. **배포**
   - 호스팅(Vercel, AWS, K8s 등)과 배포 트리거(PR, main push, 수동)
   - Preview / Production 구분 방법
   - 빌드 커맨드, Node 버전, monorepo/app 경로
   - 롤백·헬스체크·배포 승인 절차가 있으면

3. **환경 변수·시크릿**
   - 카테고리별 목록(이름만, **값은 넣지 마세요**)
   - Preview와 Production에서 달라지는 키
   - DB / 세션 / PII / 알림 / 스토리지 / cron 관련 키 관례

4. **데이터·스토리지**
   - Postgres(또는 DB) 환경별 분리 여부
   - 마이그레이션 실행 시점(빌드/배포/잡)
   - 업로드·정적 자산·CDN·캐시 헤더
   - 로컬 디스크 대신 쓰는 오브젝트 스토리지가 있으면 패턴

5. **백그라운드 작업**
   - cron / queue / worker 목록과 스케줄
   - 인증 방식(CRON_SECRET 등, 값 제외)

6. **성능·안정성에서 가져올 만한 것**
   - 이미지 최적화, 캐싱, edge/middleware, 커넥션 풀, 로그·모니터링(Sentry 등), rate limit, health check
   - “이 프로젝트에도 바로 옮기기 좋은 것”과 “직방 전용이라 제외할 것”을 구분해 주세요

7. **보안·운영 주의사항**
   - 프로덕션 시크릿이 문서/로그에 안 나가게 한 규칙
   - 개인정보·광고 데이터 관련으로 배포 시 지켜야 할 체크리스트(일반화)

출력 형식:
- 단일 마크다운 파일
- 표·불릿 위주, 파일 경로는 `path/to/file` 형태로만
- **시크릿 값, 토큰, 내부 계정, 고객 데이터, 직방 전용 비즈니스 로직 전문은 포함 금지**
- 가능하면 “landing SaaS(Next.js + Postgres + cron)에 이식 우선순위 Top 10” 섹션을 맨 앞에
